# ADR-0006: DevOS no longer configures Codex

- **Date:** 2026-08-16
- **Status:** accepted
- **Category:** tooling
- **Supersedes:** the Codex half of the tool-neutral split recorded in `claude/AGENTS.md`

## Context

DevOS installed two things into `~/.codex`: `AGENTS.md` (the tool-neutral operating
rules, the same file `~/.claude` receives) and seven skills — six vendored third-party
ones plus the proposal-only `devos-workflows`. The `devos-*` skills were deliberately
never installed there, because Codex ignores `disable-model-invocation` (verified
2026-07-27), so a manual-only skill would be auto-invocable without the user typing
anything.

On 2026-08-11 Anthropic began watermarking text from Claude models released on or after
2026-08-02. Jonathan does not want text generated by Claude carried into the Codex side
of his toolchain and asked for the integration to be removed.

The stated mechanism does not hold on its own terms, and this is recorded so the decision
is not later mistaken for a technical finding:

- `claude/AGENTS.md` last changed 2026-07-31, before watermarking began, so
  `~/.codex/AGENTS.md` never contained watermarked text.
- The only Codex-facing file this session touched was `skills-codex/devos-workflows`, by
  four lines, already reverted in `155c1d5`.
- A watermark is a statistical property of a token sequence, not metadata that propagates
  through file copies. Syncing a file to a second directory creates no new exposure.
- Codex reads `brain/` directly from the repo and never through the sync, so the one real
  carry-over path — Codex quoting Claude-written prose verbatim — is untouched by this
  change.

Jonathan was told all of the above and reaffirmed the request. It is his system, and
"I don't want this coupling" stands on its own without the watermark rationale.

## Decision

1. `sync.ps1` no longer reads or writes anything under `~/.codex`. All Codex paths,
   manifest fields (`codexAgentsMd`, `codexSkills`), plan output, and install/remove
   logic are deleted rather than gated behind a flag — a disabled code path that is
   never exercised rots.
2. The previously installed assets were removed from `~/.codex`, strictly by manifest
   entry. `codex-primary-runtime` and `ui-ux-pro-max` were present but not
   DevOS-installed and were left in place.
3. `claude/skills-codex/` stays in the repo, unreferenced. Deleting it would discard the
   proposal-only Codex variants for no benefit, and keeping it makes the decision cheap
   to reverse.
4. `AGENTS.md` keeps its tool-neutral framing and its guidance on choosing between tools,
   but now states plainly that Codex is unconfigured — so a handoff is a handoff to a
   tool with no DevOS rules loaded.

## Alternatives considered

- **A `-SkipCodex` switch.** Rejected: it leaves the reader unsure which state is
  intended, and an unexercised branch drifts. Removal is recoverable from git.
- **Reverting only the four-line Codex-facing edit.** Done first, in `155c1d5`, and it
  fully satisfied the literal goal — zero session text reaching Codex. Jonathan wanted
  the coupling gone as well, which this ADR records as a separate decision.
- **Deleting `claude/skills-codex/`.** Rejected as irreversible for no gain.
- **Keeping the six vendored third-party skills installed.** Rejected: they contain no
  Claude-generated text, but they are part of the DevOS→Codex link, and a partial cut
  would leave the manifest half-owning a directory DevOS no longer manages.

## Consequences

Codex now runs with no DevOS configuration: no task categories, no verification gate, no
memory rules, and no safety rules. Those were already enforced by instruction only, since
hooks and deny rules never transferred — so what is lost is the instruction itself, which
was the entire enforcement mechanism on that side.

The `Choosing a tool for the work` guidance in `AGENTS.md` still permits handing work to
Codex. Anyone doing so is handing it to an unconfigured tool and owns the consequences
directly; the file now says so.

The six vendored skills are gone from Codex. They can be reinstalled by hand from
`claude/skills/external/` if wanted — nothing in DevOS will do it.

If the integration is ever restored, the manifest no longer records DevOS as the owner of
those paths, so `sync.ps1` would refuse to overwrite a pre-existing `~/.codex/AGENTS.md`
rather than silently reclaiming it. That is the safe default, but it means a restore
needs the stale file removed by hand first.
